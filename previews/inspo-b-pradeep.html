Why Feature Overview / Ledger UI Mockup

01 Overview

Relay is a workplace async communication platform built for teams across different time zones. Why is a feature inside Relay — a decision ledger where teams log, organize, and retrieve the reasoning behind decisions, so context survives handoffs and onboarding.

02 Problem Space

Information lives everywhere. None of it is findable when it matters.

Decisions scatter across many surfaces — chat, design files, email, stray notes. Each captures a piece. None of them make context retrievable later.

Where decisions end up

Chat messages msg 23/40
Design file comments buried
Email threads reply 8/14
Stray notes unsynced

Who pays the cost

The New Joiner

Gets partial answers. Ramp-up is longer than it needs to be.

The Mid-Project Inheritor

Inherits outputs, not reasoning. Wrong assumptions show up as rework.

The Manager

Gets messaged constantly for context. The pattern repeats.

"Any solution that requires significant effort at the point of capture will not be used consistently. That is not a discipline problem. It is a design problem."

05 Ideation

Three directions explored

Direction 01

Single Structured Form

One form, all fields visible upfront. Clear, consistent output — but 9 fields at once feels like homework. Easy to close, rarely returned to.

Direction 02

Progressive Disclosure

Start with a single field, reveal more as user continues. Near-zero barrier to starting — but disorienting. "The form that keeps going."

Direction 03

Two Modes — Quick & Full

Quick Capture: 3 fields, under a minute. Full Entry: complete structured record. Both land in the same searchable ledger.

★ Chosen direction
